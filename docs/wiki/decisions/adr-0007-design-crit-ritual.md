# ADR-0007: Weekly Nuru Design Crit を制度化する

## Status

Proposed (Charter v0.1 と同時起票)。

## Context

ぬるぬるは「Nostr で最も優れたデザインのクライアント」を標榜する。これを個人の腕前ではなく集団の規律として持続させるには、設計判断を再現可能な儀式に落とす必要がある。Apple / Linear / Pixar Braintrust などの craft culture 組織に共通する特徴は、デザイン批評の儀式化と「やらないこと」の明文化である。

OpenAlex の論文レビュー (Zhang 2023 / Rösch 2023 / Dwivedi 2023) からも、心理的安全性を保ったままの品質基準上昇、文脈依存のデザイン規範、LLM 時代の文化希釈圧に対する制度的防壁の必要性が示唆される。

## Decision

ぬるぬるは Weekly Nuru Design Crit を制度として採用する。詳細は [[../culture/design-crit]] に記す。要点:

- **頻度**: 週1回 / 45分、議題ゼロの週でも開催。
- **構成**: 沈黙批評 → 発話批評 → 4 ラベル付け (GO / REVISE / RECONSIDER / PARK)。
- **Crit ルール**: ① 作品批評 (作者批評禁止)、② 代案必須、③ 五箇条への参照必須。
- **新規 UI 画面**は Crit を通過しない限り main にマージしない。微小変更は通常 PR レビューで進めて良い。

## Alternatives Considered

1. **完全に非同期 (PR コメントのみ)**: 速度は出るが、判断軸の共有が起きにくい。LLM 時代に文化希釈が進む。
2. **任意参加の sync 会**: 議題が無い週に開催しないと儀式が崩れる。継続性が効力の源泉。
3. **デザイン専任の judge 制**: 1人ボトルネック化、属人化。ぬるぬるは OSS なので持続性が低い。

## Why this fits NuruNuru

- **第一条「日常を壊さない」**: 表面的に新しい機能を増やす前に、体験の polish を守る制度。
- **第三条「複雑さは裏側に隠す」**: 複雑な技術を表に出さない判断を、毎週繰り返し再確認する場。
- **第四条「一貫性は新機能より重い」**: 機能追加を遅らせる判断 (REVISE / RECONSIDER / PARK) を**正当な選択肢として制度化**する。
- **やらないこと「善意の凡庸な PR をマージしない」**: 制度的に防ぐ仕組みがなければ実効しない。

## Consequences

### 良い影響

- 判断軸が共有され、新メンバーへの伝達コストが下がる。
- 「No」の言いやすさが上がる (制度の後ろ盾)。
- LLM 生成 PR の希釈圧に対する防壁になる。
- ADR 起票の母数が増え、設計判断の蓄積が進む。

### 悪い影響 / 技術的負債

- マージ速度が下がる可能性。
- ファシリテータの負担がコアメンテナに集中する。
- 形骸化リスク (対策は [[../culture/design-crit]] に記載)。

### 将来の見直し条件

- 3ヶ月運用後、開催率・GO 率・PR 滞留時間を確認し、必要なら頻度・形式を見直す。
- コアメンテナ数の変動 (3名以下 / 7名以上) で運用形態を変える可能性。
