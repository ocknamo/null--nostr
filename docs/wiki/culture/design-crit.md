# Weekly Nuru Design Crit

## Summary

ぬるぬるは「美意識を制度化する」ことを文化戦略の中核に据える。Weekly Nuru Design Crit はその主たる儀式。デザイン判断を**個人の腕前ではなく集団の規律**として再現可能にするためのもの。

## 目的

- 凡庸な UI が静かに main に混入することを防ぐ。
- レビュアー側の判断軸 ([[principles|五箇条]] / [[not-doing]] / [[../ui/design-tokens|design tokens]]) を共有する。
- 心理的安全性 (Zhang 2023) を保ったまま、品質基準を上げる。

## 頻度と所要時間

- 週1回 / 45分。
- 議題が無い週でも、開催はする (継続性が儀式の効力)。

## 参加者

- コアメンテナ全員。
- 該当 PR / RFC の起案者 (任意で外部コントリビュータ含む)。
- LLM エージェントは観察役として議事ログを生成する (詳細: [[llm-onboarding]])。

## アジェンダ (固定 5 セクション)

1. **前回宿題の追跡** (5分): 前回出た action item の現況確認。
2. **議題プレゼン** (1議題あたり5分): 起案者が PR / モック / 実機ビルドを共有。
3. **沈黙批評** (3分): 全員が無言で観察し、各自メモ。第一印象の汚染を避ける。
4. **発話批評** (1議題あたり10分): 後述の Crit ルールに従って発話。
5. **判断とラベル付け** (5分): 4種のラベルから1つを付ける (後述)。

## Crit ルール (3つ)

1. **作品を批評する。作者を批評しない。**「これは〜が弱い」と言い、「あなたは〜が弱い」と言わない。
2. **代案を必ず添える。**「ダメ」だけは禁止。「ダメ、なぜなら X、代わりに Y はどうか」と言う。
3. **五箇条への参照を1回は入れる。**「これは第三条 (複雑さを隠す) に反している」など、共有規約に紐づけて話す。

これらは Pixar の Braintrust ルールから着想し、ぬるぬるの五箇条運用に合わせて改変したもの。

## 4 判断ラベル

| ラベル | 意味 | 次のアクション |
|---|---|---|
| **GO** | このまま進めて良い | 起案者がマージまで進める |
| **REVISE** | 方向性は正しいが具体実装に修正が必要 | 起案者が修正、次の Crit で再提示 |
| **RECONSIDER** | 課題設定そのものを見直す必要 | 起案者が問題定義から書き直す |
| **PARK** | 今は議論する材料が足りない / 優先度が低い | Issue として残し、トリガー条件を明記 |

ラベルは多数決ではなくファシリテータが判定する。異論があれば ADR で残す。

## ファシリテータ

- 週ごとの輪番 (コアメンテナ間で)。
- 役割: 時間管理、Crit ルール違反の指摘 (例:「今のは作者批評になっている」)、ラベル決定。

## 議事ログ

- `docs/wiki/culture/crit-logs/YYYY-WW.md` に残す (本ページのリポジトリには未作成。初回開催時に追加)。
- 議事には参加者・議題・ラベル・action item のみ。発言の逐語記録はしない (心理的安全性のため)。

## 非目標 (Non-goals)

- Crit は**承認会議ではない**。GO ラベルがなくてもマージ可能な微小変更は通常通り PR レビューで進める。
- Crit は**ブレストではない**。新規アイデアを発散する場ではなく、提案された案を磨く場。
- Crit は**勝ち負けではない**。「自分の案が REVISE になった = 負け」ではない、というカルチャーを最初の数回で確立する。

## 失敗モードと対策

| 失敗モード | 兆候 | 対策 |
|---|---|---|
| 仲良し化 | 全議題が GO ばかりになる | ファシリテータが REVISE / RECONSIDER を意識して使う |
| 派閥化 | 同じ人の案だけが通る | 沈黙批評を厳格化し、起案者名を伏せて提示する週を設ける |
| 形骸化 | 議題が PR 全てになる / 短時間化する | 議題は週3件まで、それ以外は通常レビューに戻す |
| 萎縮 | 新メンバーが PR を出さなくなる | 「失敗作 Crit」回を月1で設け、コアメンテナの失敗を晒す |
