Decision: **Australia 28,218 impressions / 0 downloads is treated as an anomaly until proven otherwise.** It should not be used as evidence of Australian demand yet.

Possible explanations:

- bot / crawler / monitoring traffic;
- Zapstore impression counting includes list/card exposures rather than app-detail intent;
- country detection skew from CDN/proxy/VPN;
- Zapstore-side analytics bug;
- Download action not visible/usable for the traffic source;
- international users do not understand the app value or install path.

Follow-up checks:

1. Ask/inspect Zapstore impression definition.
2. Check day-by-day Australia distribution.
3. Check referrer/source if available.
4. Compare other Zapstore apps for the same Australia spike.
5. Check whether download button works for target devices/regions.

## Block article synthesis

Block's article argues that companies historically used hierarchy because humans had limited span of control. AI can replace much of what hierarchy did: routing information, maintaining alignment, and coordinating work.

The article's model maps to ぬるぬる as follows.

### Capabilities

Reusable abilities rather than isolated features.

Current ぬるぬる capabilities include:

- passkey onboarding;
- Nostr note publishing;
- profile setup and profile sharing;
- post sharing and event landing pages;
- image upload;
- relay connection and relay-targeted publishing;
- notifications;
- Android / iOS / Web interfaces;
- Google Play / App Store / Zapstore distribution.

This week should harden existing capabilities rather than add large new ones.

### Company world model

The project's shared model of itself:

- `AGENTS.md`;
- `docs/wiki/`;
- ADRs;
- ThemaDAY minutes;
- release artifacts and version metadata;
- store metrics;
- crash / ANR reports;
- CI/build status;
- user feedback.

Decision: `docs/wiki/` should be treated as the durable company world model for agent coordination.

### Customer world model

The project's model of user reality:

- installs;
- product page views;
- first-launch success;
- passkey registration success;
- first-post completion;
- time from registration to first post;
- profile share count;
- post share count;
- share-link visits;
- store conversion;
- crash / ANR;
- uninstall / retention;
- qualitative feedback.

Current gap: first-post completion, share execution, and share-to-install/return behavior are not yet sufficiently visible.

### Intelligence layer

For ぬるぬる, the intelligence layer is the combination of:

- ThemaDAY;
- multiple AI agents;
- store and product data;
- repository/wiki knowledge;
- human final judgment.

Decision: roadmap should be generated from observed user failures, not from feature appetite alone.

Examples:

| Observed failure | Roadmap implication |
|---|---|
| Registered users do not post | Improve first-post onboarding/copy/CTA |
| Posts are not shared | Improve share button placement/copy/success prompt |
| Shared links do not convert | Improve OGP, landing page, and store CTA |
| Zapstore impressions do not download | Investigate signal quality and store metadata |
| Users post once and do not return | Improve notification/reaction/feedback loop |

### Interfaces

Interfaces are delivery surfaces, not the whole value:

- Android app;
- iOS app;
- Web PWA;
- `/p/<npub>` profile invite landing pages;
- `/e/<event-id>` post preview pages;
- Google Play listing;
- App Store listing;
- Zapstore listing;
- Nostr events themselves.

## Weekly operating model

Use lightweight DRI ownership instead of broad feature ownership.

| DRI | Scope | Output this week |
|---|---|---|
| Onboarding DRI | Registration to first post | Friction list and copy improvements |
| Share Loop DRI | Profile/post share to new-user flow | Share preview checklist and fixes |
| Store Trust DRI | Google Play / App Store / Zapstore | Store data report and metadata changes |
| Quality DRI | Crash/ANR/first-run path | Quality gate result |
| Signal DRI | Metrics and learning loop | Minimal KPI dashboard or manual daily report |
| Wiki DRI | Company world model | ThemaDAY decisions recorded in `docs/wiki/` |
