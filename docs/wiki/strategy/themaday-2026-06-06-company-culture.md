# ThemaDAY 2026-06-06 — 企業文化 / カルチャー構築と開かれた言論

## Status

**Accepted** — 2026-06-06。ユーザー承認済み。ただし、検討案に含まれていた **iOS / Android ネイティブアプリの投稿制限は不採用** として明示的に取り下げる。

## Summary

ぬるぬるは、Apple / Google の配布支配と中央集権 SNS のネットワーク効果に正面から勝つことを目標にしない。代わりに、**開いたプロトコルの上に、小さく信頼された日本語の共同体を作る**。

結論を先に書く:

1. **巨大 SNS と同じ市場を取りに行かない。** ぬるぬるは「大きな広場」ではなく「小さな庭」を作る。
2. **言論の自由は、全員のタイムラインに届く権利ではない。** 発言・公開・引用・退出の自由と、表示・到達・推薦の権限を分ける。
3. **プロトコルは開く。主要 UI は関係性で絞る。** Home はフォロー graph、News / Mini Apps は 2-hop trust graph、初回体験は safe starter graph を使う。
4. **ネイティブ投稿制限はしない。** iOS / Android / Web はいずれも投稿できるクライアントとして維持する。ストア・安全リスクは投稿導線の遮断ではなく、表示面のスコープ、リレー生フィード削除、ミュート / ブロック / report、NIP-70 等で扱う。
5. **小さな政府、小さな LINE。** ルールは少なく、境界は明確に、鍵と退出可能性はユーザー側に残す。

## Context

ハードウェア / OS / ストアは Apple と Google が強く握っている。SNS サービス市場も LINE / X / Meta / TikTok など数社に集約され、ネットワーク効果・広告・推薦アルゴリズム・クリエイター分布で後発が正面から覆すのは難しい。

同時に、中央集権 SNS ではアカウント停止、アルゴリズム非表示、ストア規約、決済遮断がそのまま表現経路の喪失につながる。ぬるぬるが扱うべき自由は、巨大 SNS の代替市場を取ることではなく、**ユーザーが鍵・関係・言葉を持ったまま移動できる退出路**を日常体験にすること。

## Current behavior

- [[../decisions/adr-0013-relay-feed-removal]] により、任意リレー生フィードは主要 UI から削除済み。
- [[june-2026-roadmap]] は Home のコンテンツ面をフォローフィード中心へ移し、News / Mini Apps を 2-hop 信頼グラフ型にする方針を持つ。
- [[../decisions/adr-0020-safe-starter-graph]] は、初回 Home の空白離脱を避けるため safe starter graph を Proposed として記録している。
- Web / Android / iOS には投稿導線が存在し、140文字制限、返信、画像、NIP-70、リレー指定投稿などをそれぞれの platform guardrails 内で扱う。

このページは文化・戦略判断であり、単独では実装変更を伴わない。実装変更時は対応する feature / platform wiki と ADR を更新する。

## 1. 言論の自由の定義

ぬるぬるで扱う「言論の自由」は、次の自由を指す。

| 含むもの | 説明 |
|---|---|
| 発言する自由 | 国家・プラットフォーム・多数派に事前許可されずに言葉を発すること。 |
| 公開 / 出版する自由 | 自分の署名でイベントや記事を公開できること。 |
| 引用 / 批判する自由 | 反対意見や批評が許されること。 |
| 聞かない自由 | ミュート、ブロック、フォロー解除、リレー選択により距離を取れること。 |
| 退出 / 移住する自由 | 鍵・関係・投稿を一社に人質化されず、別クライアント / 別リレーへ移れること。 |

一方で、次は言論の自由そのものではない。

| 含まないもの | 理由 |
|---|---|
| 全員のタイムラインに表示される権利 | 発言権と到達権は別。クライアントや共同体には編集・表示選択の自由がある。 |
| 他人の共同体に居座る権利 | 共同体は境界を持つ。境界がなければ荒らし・スパム・声の大きさに支配される。 |
| 推薦アルゴリズムで拡散される権利 | 推薦は共同体・編集・信頼関係の設計であり、無条件の権利ではない。 |
| 違法・破壊的コンテンツを主要 UI に流す権利 | ストア公開品質、日常体験、共同体保全と衝突する。 |

要約すると、ぬるぬるは **発言権を守り、到達権を関係性で設計する**。

## 2. 思想的背景

言論の自由は一人の思想家が発明したものではなく、複数の制度・思想の積み重ねで形成された。

| 人物 / 理論 | ぬるぬるへの示唆 |
|---|---|
| ジョン・ミルトン『アレオパジティカ』 | 出版許可制への反対。事前許可なしに公開できることの重要性。 |
| ジョン・スチュアート・ミル『自由論』 | 人間は誤りうるため、異論を封じてはいけない。間違った意見にも討論上の価値がある。 |
| ジェームズ・マディソン / 米国修正第1条 | 政府による言論制限への警戒。 |
| ホームズ / ブランダイス判事 | 思想の自由市場、危険な言論への対抗としての counter-speech。 |
| トクヴィル | 国家だけでなく、多数派の世論も自由を圧迫しうる。 |
| ハーバーマス | 権力から独立した公共圏の必要性。 |
| カール・ポパー | 無制限の寛容は、寛容そのものを破壊する勢力を許しうる。 |
| ラザースフェルド / カッツの二段の流れ仮説 | 人はマスメディアから直接ではなく、信頼するオピニオンリーダーや近い関係を通じて情報を受け取る。 |

ぬるぬるは、ミル的な「異論を残す自由」と、ポパー的な「共同体破壊への境界」を同時に持つ。

## 3. 市場戦略 — 巨大 SNS と違うゲームをする

中央集権 SNS と同じ KPI を追うと負ける。ぬるぬるは以下を競争軸にしない。

- DAU / WAU の最大化
- 滞在時間の最大化
- 無限スクロールによる中毒設計
- グローバル最新投稿の量
- アルゴリズム推薦の強さ
- クリエイターの大量獲得キャンペーン

代わりに、次を強みにする。

| 巨大 SNS | ぬるぬる |
|---|---|
| 市場を取る | 関係を守る |
| 発見を売る | 紹介を育てる |
| 全員を広場へ集める | 小さな庭を複数作る |
| アカウントを預かる | 鍵を本人に返す |
| 自由を規約で許可する | 自由を退出可能性として設計する |

## 4. Product doctrine

### 4.1 Open protocol, bounded surfaces

- Nostr protocol / relay / key は開いたままにする。
- 主要 UI は任意リレー全件ではなく、フォロー、2-hop、safe starter graph、手動 curated list、コミュニティ境界で絞る。
- リレー生フィード削除は、言論の自由の否定ではなく、**表示面の編集判断**として扱う。

### 4.2 Native posting parity

ネイティブアプリだけ投稿不可にする案は採用しない。

| 採用しない案 | 不採用理由 |
|---|---|
| iOS / Android は閲覧中心、PWA / Desktop だけ投稿可能 | 日常を壊す。スマホ中心ユーザーを発言者から外す。platform parity と「主権的コミュニケーション」に反する。 |
| ストアリスクを投稿禁止で避ける | 問題の中心は投稿行為ではなく、主要 UI に何を無条件表示するか。 |

採用する方針:

- Android / iOS / Web の投稿導線を維持する。
- ストア・安全リスクは、リレー生フィード廃止、2-hop trust graph、safe starter graph、ミュート / ブロック / report、NIP-70 protected events、コピー審査配慮で扱う。
- 1プラットフォームだけ投稿能力を落とす場合は、別途 ADR と Design Crit を必須にする。

### 4.3 Two-step flow / invitation as context

二段の流れ仮説は、ぬるぬるの発見設計に合う。

- 「人気」ではなく「誰が紹介したか」を重視する。
- フォロー中の人、近い人、信頼できる starter graph を導線にする。
- 招待は身分ではなく文脈。招待者はリンクだけでなく、最初に見る人・読む投稿・入る場所・ふるまいの温度感を渡す。
- 初回 Home は空白を避けるが、自動フォローは別 ADR なしに行わない。

### 4.4 Small government, small LINE

- ルールは少なく、境界は明確にする。
- 中央運営が全てを裁かない。ミュート / ブロック / リレー / クライアント / コミュニティで責任を分ける。
- LINE 的な日常の手触りを目指すが、LINE 的なアカウント人質化はしない。
- 鍵、関係、退出可能性をユーザー側に残す。

## 5. Guardrails

- 任意リレー生フィードを主要導線へ復活させない。
- 「誰でも投稿できる」を「誰でも全員に届く」と説明しない。
- ネイティブ投稿制限を採用しない。
- 招待 / starter graph を特権階級化しない。
- starter list を公式おすすめユーザーとして強く見せすぎない。
- 政治・宗教・成人向け・違法性が高い文脈を Phase 0 starter graph に入れない。
- Nostr / relay / graph / NIP の語を初心者向け UI に出さない。
- 数字を理由に [[../culture/principles|五箇条]] を曲げない。

## 6. Better metrics

短期の巨大 SNS 型 KPI ではなく、次を観察する。

| 観察したいもの | 理由 |
|---|---|
| Week-1 復帰率 | 初回 Home / starter graph が日常に接続できているか。 |
| 初投稿率 | 発言導線が壊れていないか。native posting parity の確認にもなる。 |
| 返信 / 反応の質 | 関係密度の proxy。 |
| 招待後の定着 | 招待が文脈として機能しているか。 |
| ミュート / ブロック / report の発生 | 境界設計の健康状態。 |
| 文化適合 PR / Design Crit 記録 | 開発者コミュニティが拡大しても美意識を守れているか。 |
